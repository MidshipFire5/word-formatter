# Word Formatter

Приложение для Windows и Linux, которое приводит документ Word (`.docx`)
к требованиям выбранного профиля оформления: шрифт, поля, отступы, интервалы,
заголовки, подписи, таблицы, сноски и нумерация страниц.

**Главный принцип: меняется оформление, а не содержание.** Текст не
переписывается, таблицы и изображения не удаляются, исходный файл остаётся
неизменным — результат сохраняется в отдельный документ.

Единственное исключение — подпись, оказавшаяся не на своём месте: если
методичка требует, чтобы подпись рисунка стояла под рисунком, а в документе
она стоит над ним, приложение перенесёт подпись. Текст подписи при этом
не меняется, и каждый перенос указан в отчёте.

Пример: студент выбирает профиль «Финансовый университет, Краснодарский
филиал — письменные работы (2026)», загружает курсовую и получает документ,
оформленный по методическим указаниям кафедры.

## Что приложение делает

- Формат листа, ориентация, поля страницы, расстояния до колонтитулов.
- Основной текст: шрифт, размер, выравнивание по ширине, отступ первой
  строки, межстрочный интервал, интервалы до и после абзаца.
- Снимает курсив и подчёркивание, если это запрещено профилем, и перечисляет
  каждое такое место в отчёте.
- Заголовки: структурные части (ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ и подобные) — прописными
  по центру, разделы и подразделы — с абзацного отступа. Дополнительно
  обновляются стили заголовков Word, чтобы работало автоматическое содержание.
- Подписи рисунков и названий таблиц: оформление и **положение**. Подпись
  рисунка ставится под рисунком, название таблицы — над таблицей. Если
  в документе было наоборот, подпись переносится, и об этом сообщается
  в отчёте. Текст подписи не изменяется.
- Таблицы: шрифт 12 пт, одинарный интервал, выравнивание шапки, чисел и текста.
- Элементы перечислений (маркеры не заменяются).
- Сноски: размер и интервал через стиль сносок.
- Нумерация страниц полем Word: внизу по центру, со второй страницы.
- Автоматическая расстановка переносов (в заголовках и подписях переносы
  запрещаются).
- Свободные строки между заголовками и текстом, выше и ниже таблиц, рисунков
  и формул.
- Проверка сохранности содержимого после обработки и отчёт об изменениях.

## Чего приложение не делает

Мы считаем важным сказать это прямо:

- **не переписывает текст** и не исправляет формулировки;
- **не создаёт титульный лист** — методичка не задаёт его оформление;
- **не пересчитывает автоматическое содержание**: приложение помечает поле как
  требующее обновления, а пересчитывает его Word при открытии;
- **не переоформляет формулы** и встроенные объекты (редактор формул) —
  сообщает о них в отчёте;
- **не заменяет маркеры списков** на тире — оформляет только абзацы;
- **не исправляет содержание**: если в документе нет заголовков, оформленных
  стилями или начинающихся с номера, приложение не станет угадывать.

Спорные абзацы (например, абзац со стилем заголовка, но длинный и с точкой
в конце) **не оформляются** и попадают в раздел «Требует ручной проверки».

## Системные требования

- **Python 3.10 или новее** (рекомендуется 3.11+). Проверено на 3.11.
- Windows 10 и 11 или Linux (Ubuntu и совместимые).
- Около 400 МБ свободного места: зависимости и локальное окружение `.venv`.
- Интернет **только при первом запуске** — чтобы скачать зависимости.
  Дальше приложение работает без интернета.
- Права администратора не нужны. Приложение не устанавливается в систему.

Зависимости: `python-docx` (работа с документами Word), `PySide6-Essentials`
(интерфейс), `lxml`. Точные версии — в `requirements.txt`.

`PySide6-Essentials` — это PySide6 без дополнений (3D, WebEngine, Charts):
приложению нужны только QtWidgets, QtCore и QtGui, поэтому загрузка втрое
меньше.

## Запуск в Windows

1. Скачайте проект: кнопка **Code → Download ZIP** на странице репозитория.
2. Распакуйте архив **целиком** в удобную папку. Важно распаковать, а не
   открывать из архива: приложение создаёт рядом с собой окружение `.venv`.
3. Двойной щелчок по `run_windows.bat`.

При первом запуске скрипт:

1. найдёт установленный Python и проверит его версию;
2. если Python нет или версия старая — покажет инструкцию по установке
   и завершит работу;
3. создаст локальное окружение `.venv` в папке программы;
4. скачает и установит зависимости (нужен интернет, это займёт несколько минут);
5. запустит приложение.

При следующих запусках шаги 3 и 4 пропускаются: скрипт проверяет отпечаток
`requirements.txt` и устанавливает зависимости только если файл изменился.
Повторный запуск занимает доли секунды.

Если Python установлен из Microsoft Store, он не подходит: запустите
`run_windows.bat` и следуйте инструкции на экране — нужна версия с сайта
[python.org](https://www.python.org/downloads/windows/) с галочкой
«Add python.exe to PATH».

## Запуск в Linux

```bash
git clone <адрес репозитория>
cd word-formatter
bash run_linux.sh
```

Если файл помечен как исполняемый, можно запустить короче: `./run_linux.sh`.
Если система не позволяет запустить файл напрямую, используйте запасной
способ:

```bash
bash run_linux.sh
```

После клонирования репозитория проверьте право на исполнение:

```bash
chmod +x run_linux.sh
```

Скрипт делает то же, что и в Windows. Если не хватает системных библиотек
для графического интерфейса, скрипт скажет, что именно установить, например:

```bash
sudo apt update && sudo apt install -y libgl1 libegl1 libxkbcommon-x11-0 \
  libxcb-cursor0 libxcb-icccm4 libxcb-keysyms1 libxcb-shape0 \
  libxcb-xinerama0 libdbus-1-3
```

Если в системе нет модуля `venv` (бывает в Ubuntu с минимальной установкой),
установите его: `sudo apt install -y python3-venv`.

## Ручной запуск через main.py

Если окружение уже подготовлено, приложение можно запустить напрямую:

```bash
# Windows
.venv\Scripts\python.exe main.py

# Linux
.venv/bin/python main.py
```

Если окружения ещё нет, его нужно создать и заполнить один раз:

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements.txt   # Windows: .venv\Scripts\python.exe
python main.py
```

Дополнительные команды без графического интерфейса:

```bash
python main.py --version         # версия приложения
python main.py --list-profiles   # список профилей оформления и папки, где они лежат
python tools/bootstrap.py --setup-only   # только подготовить окружение, без запуска
```

## Как пользоваться

1. Выберите профиль оформления в списке слева. Справа появится описание:
   источник требований, оформление и то, чего профиль не делает.
2. Нажмите **«Выбрать файл Word»** и выберите документ `.docx`.
   Старый формат `.doc` нужно предварительно сохранить как `.docx`.
3. Нажмите **«Применить оформление»**.
4. Укажите, куда сохранить результат. По умолчанию предлагается имя
   `<имя>_оформлено.docx` рядом с исходным документом.
   **Сохранить поверх исходного файла нельзя** — приложение это запрещает.
5. Прочитайте отчёт и, при необходимости, сохраните его кнопкой
   **«Сохранить отчёт…»**.

Откройте сохранённый файл в Word и нажмите `Ctrl+A`, затем `F9` — Word
обновит номера страниц и автоматическое содержание.

## Профили оформления

Профиль — это файл JSON с параметрами оформления. Профили лежат в двух местах:

| Где | Назначение |
|---|---|
| `profiles/` рядом с программой | встроенные профили, обновляются вместе с проектом |
| Windows: `%APPDATA%\WordFormatter\profiles`<br>Linux: `~/.config/WordFormatter/profiles` | ваши личные профили |

Личный профиль с тем же `id`, что и встроенный, **заменяет** встроенный.
Это позволяет исправлять параметры под свою кафедру, не трогая папку проекта.

Добавить новый профиль — значит положить JSON-файл в папку личных профилей:
**менять код приложения для этого не нужно**. Полное описание формата со всеми
полями — в [docs/PROFILES.md](docs/PROFILES.md).

Если в файле профиля есть ошибка (опечатка в имени поля, неверное значение),
приложение не станет применять его молча: профиль появится в списке с пометкой
об ошибке и объяснением, что именно не так.

Поставляемый профиль `fu-krasnodar-2026` собран по методическим указаниям
Краснодарского филиала Финуниверситета (2026) и **не является
демонстрационным**: его параметры сверены с таблицей 1 методички
(это проверяется тестом).

## Отчёт об обработке

После обработки приложение показывает отчёт из четырёх частей:

1. **Что сделано** — по каждому правилу, с количеством обработанных абзацев.
2. **Требует ручной проверки** — спорные абзацы с причиной, объединённые
   ячейки таблиц, формулы и встроенные объекты, замечания о титульном листе
   и содержании.
3. **Ограничения профиля** — что данный профиль сознательно не делает.
4. **Проверка сохранности содержимого** — сравнение исходного документа
   и результата по тексту, таблицам, изображениям, гиперссылкам, сноскам,
   полям и объектам.

Отчёт можно сохранить в текстовый файл.

## Если что-то не работает

| Что видно | Что делать |
|---|---|
| «Не найден Python» | Установите Python 3.10+ с [python.org](https://www.python.org/downloads/windows/) с галочкой «Add python.exe to PATH». Версия из Microsoft Store не подходит. |
| Ошибка при установке зависимостей | Нужен интернет. Проверьте подключение и запустите скрипт снова. |
| «Не удалось создать локальное окружение» | Linux: `sudo apt install -y python3-venv`. Windows: проверьте права на запись в папку программы. |
| Qt не запускается (Linux) | Установите системные библиотеки: команда приведена в сообщении скрипта. |
| «Файл сохранён в старом формате Word» | Откройте документ в Word: «Файл → Сохранить как → Документ Word (*.docx)». |
| «Файл защищён паролем» | Снимите защиту в Word: «Рецензирование → Ограничить редактирование». |
| Пустой список профилей | Проверьте, что папка `profiles` скопирована вместе с программой. |
| Приложение не видит мой профиль | Проверьте, что файл лежит в папке личных профилей (её путь печатает `python main.py --list-profiles`) и что он корректен как JSON. |
| «У вас нет разрешения на сохранение файлов в этом месте» | Папка закрыта для записи. Сохраните результат в папку самой программы или в «Документы». Если приложение запущено из среды разработки или из программы с ограничениями, скопируйте проект в обычную папку (например, `C:\WordFormatter`) и запустите заново |

Полезно посмотреть журнал работы: `%APPDATA%\WordFormatter\logs\word-formatter.log`
(Windows) или `~/.config/WordFormatter/logs/word-formatter.log` (Linux).
