# Спецификация MVP

Документ фиксирует, что именно входит в первую версию приложения, какие
решения приняты и по каким признакам результат считается готовым.
Он составлен по согласованию с заказчиком и служит точкой отсчёта: если
поведение приложения расходится с этим документом, прав либо документ,
либо код.

## 1. Назначение

Локальное настольное приложение для Windows и Linux, которое приводит готовый
документ Word (`.docx`) к требованиям выбранного профиля оформления.

Главный принцип: **меняется оформление, а не содержание**. Приложение
не переписывает текст, не исправляет формулировки, не удаляет элементы
документа и никогда не изменяет исходный файл.

Единственное исключение из этого правила оговорено отдельно: приложение может
перенести подпись рисунка или название таблицы, если профиль требует другого
их положения. Текст подписи не меняется, и каждое перемещение попадает
в отчёт.

## 2. Пользователь и основной сценарий

Пользователь — студент или сотрудник, которому нужно привести работу
к требованиям методички кафедры, без знания программирования.

1. Пользователь получает проект из GitHub (Download ZIP или клонирование).
2. Запускает `run_windows.bat` (Windows) или `bash run_linux.sh` (Linux).
3. Скрипт готовит локальное окружение `.venv` и запускает приложение.
4. В окне выбирает профиль оформления и документ Word.
5. Нажимает «Применить оформление» и указывает, куда сохранить результат.
6. Читает отчёт: что изменено, что нужно проверить вручную, цело ли содержимое.

## 3. Согласованные решения

| Вопрос | Решение |
|---|---|
| Параметры профилей | Взять из методических указаний заказчика, а не придумывать |
| Способ применения правил | Гибрид: изменение определений стилей Word **и** назначение стилей абзацам по анализу структуры |
| Ручное (прямое) форматирование | Снимать; абзацы, роль которых неясна, не оформлять и выводить в отчёт |
| Объём первой версии | Расширенный: страница, текст, заголовки, списки, таблицы, подписи, сноски, номера страниц, переносы, свободные строки |
| Проверка на Linux | Автотесты в CI для Windows и Linux; фактический запуск в Linux проверяет заказчик |
| Хранение профилей | Встроенные рядом с программой, личные — в папке пользователя; редактор профилей отложен |
| Название | Word Formatter |
| Лицензия | MIT — код можно использовать, изменять и распространять |
| Свободные строки | Вставлять пустыми абзацами автоматически, с предохранителями и отчётом |
| Курсив и подчёркивание | Снимать везде, где найдено, и перечислять каждое место в отчёте |
| Номера страниц | Ставить самим; разрывы страниц и содержание — только в отчёт |
| Ссылки на шрифт | Всегда писать `Times New Roman`; на Linux шрифт не подменяется |
| Таблицы | Дополнительно выравнивать ячейки по типу данных (шапка, числа, текст) |
| Положение подписей | Переносить подпись рисунка под рисунок и название таблицы над таблицей, если профиль этого требует (единственное изменение порядка элементов) |

## 4. Профиль `fu-krasnodar-2026`

Источник: «Методические указания по оформлению письменных работ»,
Краснодарский филиал Финуниверситета, 2026 (сост. А. С. Молчан,
О. Ю. Франциско), таблица 1.

| Правило | Значение |
|---|---|
| Формат листа | A4, книжная ориентация |
| Поля | левое 30, правое 15, верхнее 20, нижнее 20 мм |
| Колонтитулы | верхний 20 мм, нижний 12,5 мм |
| Шрифт | Times New Roman |
| Основной текст | 14 пт, по ширине, первая строка 1,25 см, интервал 1,5, до и после абзаца 0 пт |
| Курсив и подчёркивание | не допускаются, снимаются |
| Таблицы | 12 пт, одинарный интервал, название над таблицей без абзацного отступа |
| Выравнивание в таблицах | шапка по центру, числа по центру, текст по левому краю, прочерки не трогаются |
| Сноски | 10 пт, одинарный интервал |
| Структурные заголовки | «ВВЕДЕНИЕ», «ЗАКЛЮЧЕНИЕ», «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ», «СОДЕРЖАНИЕ», «ПРИЛОЖЕНИЕ»: прописными, по центру, без абзацного отступа, 14 пт, полужирный, одинарный интервал |
| Разделы и подразделы | с абзацного отступа, по ширине, 14 пт, полужирный, одинарный интервал, без переносов |
| Подписи рисунков | «Рисунок N – Название»: по центру, без абзацного отступа, 14 пт, без переносов |
| Нумерация страниц | арабские, сквозная, внизу по центру, 12 пт, без точки, начиная со второй страницы |
| Переносы | автоматические, кроме заголовков, названий таблиц и рисунков |
| Свободные строки | между заголовками и текстом, выше и ниже таблиц, рисунков и формул |

## 5. Что входит в первую версию

- Разбор структуры документа и определение роли каждого абзаца.
- Правила оформления по разделам 4 и 5 спецификации.
- Отчёт об изменениях и о том, что требует ручной проверки.
- Проверка сохранности содержимого после обработки.
- Графический интерфейс на PySide6: выбор профиля, выбор файла, обработка,
  отчёт, сохранение результата и отчёта.
- Скрипты запуска для Windows и Linux с подготовкой окружения.
- Профили в JSON, встроенные и личные; проверка файла профиля.
- Создание профиля из своей методички: чтение Word, PDF и текста, разбор
  требований из текста, измерение оформления файла-образца, показ найденного
  человеку и сохранение профиля в личную папку.
- Встроенные профили: методические указания Финуниверситета (Краснодарский
  филиал, 2026) и ГОСТ 7.32-2017.
- Автоматические тесты и непрерывная интеграция для Windows и Linux.
- Документация для пользователя и для разработчика.

## 6. Чего в первой версии нет

- Создание титульного листа.
- Пересчёт автоматического содержания.
- Переоформление формул и встроенных объектов.
- Замена маркеров списков на тире.
- Обработка старого формата `.doc` и документов с макросами `.docm`.
- Сборка в EXE и системный установщик.
- Редактор профилей в интерфейсе: созданный из методички профиль можно
  посмотреть и сохранить, но изменить в окне отдельное значение нельзя —
  правка выполняется в JSON-файле.
- Чтение сканированных методичек (PDF без текстового слоя) — нужен OCR.
- Разбор ссылок на стандарты («оформление по ГОСТ 7.32-2017») без самих
  требований: приложение не подставляет требования стандарта по упоминанию.
- Перевод интерфейса на другие языки.

## 7. Критерии готовности

1. Проект можно получить из GitHub и запустить на Windows и Linux по
   инструкции, без EXE и без прав администратора.
2. Работают все три способа запуска: `run_windows.bat`, `run_linux.sh`,
   `main.py`; повторный запуск не переустанавливает зависимости.
3. Отсутствие Python или ошибка установки зависимостей дают понятное
   сообщение с указанием, что делать.
4. Пользователь выбирает профиль и документ, получает результат и отчёт.
5. Результат соответствует каждому пункту таблицы профиля — проверяется
   тестами на параметры.
6. Исходный файл не изменяется.
7. Сохранность содержимого подтверждена тестами: текст, таблицы, изображения,
   гиперссылки, сноски, списки, колонтитулы, разрывы разделов, поля.
8. Ошибочные и неподдерживаемые файлы обрабатываются с понятным сообщением.
9. Результат открывается в Word и LibreOffice; расхождения не скрываются.
10. Добавление нового профиля — это новый JSON-файл, без правки алгоритма;
    проверено тестом.
11. Тесты проходят на Windows и Linux в непрерывной интеграции.
12. Новый пользователь запускает проект по README без помощи разработчика.

## 8. Открытые вопросы

- Титульный лист: нужен ли отдельный профиль титульного листа.
- Нужен ли редактор профилей в интерфейсе.
- Нужна ли кнопка «Открыть результат в Word» после обработки.
- Стоит ли добавлять проверку орфографии и нормоконтроль (не входит в MVP).
